security:
Imagine you built a treehouse but forgot to lock the door. A stranger could get inside. That's like a security problem in code.

Reliability:
Will our application work correctly without crashing?

Maintainability:
Is the code easy for other people to understand and fix?

Hotspots:
Hotspots are pieces of code that might be dangerous from a security point of view and need someone to look at them.

Coverage:
Coverage asks: How much of our code is being tested automatically?

Duplications:
How much code is repeated?

Quality Profiles:
Collection of rules, that tells a code-quality tool what to check in your code.

For example, in SonarQube, a Quality Profile might contain rules such as:

Don't store password in code
String password = "12345";

Quality Gate:
Quality Gate = A pass/fail checkpoint that decides whether your code is good enough to move forward.

SonarQube Administration

1. Analysis Scope 

    Tells SonarQube which code/files it should check.
    Also allows you to ignore certain files or folders.

2. Authentication 

    Controls who can log in to SonarQube.
    Decides how users prove they are allowed to enter.

3. DevOps Platform Integrations 

    Connects SonarQube with tools such as:

      GitHub
      GitLab
      Azure DevOps
    Helps SonarQube work together with your source-code platform.

4. Early Access Features 

    Allows you to try new features.
    These features may still be under testing.

5. Email Notification 

    Controls when SonarQube sends emails.
    For example:

      Quality Gate failed
      Project analysis completed
      Code quality problems

6. External Analyzers 

    Controls analysis information coming from other tools.
    These tools can provide additional information about your code.

7. General 

    Contains general SonarQube settings.
    Settings that don't belong to another specific category are usually here.

8. Housekeeping 

    Cleans up old SonarQube data.
    Helps prevent the SonarQube database from becoming unnecessarily large.

9. JaCoCo 

    Used for Java code coverage.
    Helps answer:

     > "How much of my Java code is covered by tests?"

10. Languages 

     Contains settings for different programming languages.
     Examples:

       Java
       JavaScript
       C#
       Python

11. Mode 

     Controls how SonarQube works in certain analysis/configuration modes.

12. New Code 

     Defines what SonarQube considers new code.
     Helps SonarQube focus on problems introduced by recent changes.

13. SCM 

     SCM means Source Code Management.
     Connects SonarQube with Git information.
     Helps identify:

       Who changed the code
       When it was changed
       Which lines were changed

14. Security 

     Controls security-related settings.
     Helps SonarQube identify and manage security problems in your code.

15. Technical Debt 

     Estimates the time/effort required to fix code problems.
     Example:

      > "This code has problems that may take 3 hours to fix."
