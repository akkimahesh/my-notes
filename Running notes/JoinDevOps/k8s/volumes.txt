EBS
===
when data is stateful we use ebs.
1. create ebs in same AZ where worker node present.
2. install the ebs drivers for k8 to understand ebs
kubectl apply -k "github.com/kubernetes-sigs/aws-ebs-csi-driver/deploy/kubernetes/overlays/stable/?ref=release-1.58"
3. your worker nodes should ebs permission to mount the disk. attach AmazonEBSCSIDriverPolicy to the workernode IAM role to provide authorization

we can use below access modes for EBS
1. ReadWriteOnce 
2. ReadWriteOncePod

Reclaim policies
===========
Retain -> keep the disk and data even the node is deleted
Delete -> Delete the disk
Recycle -> Delete the data in disk, but keep the disk


PV(Persistant Volume)
=====================
1. Here PV checks ebs is really exist or not.
1. Physical representation of the disk
2. Equivalant object/resource for the disk inside k8S cluster

PV is not just used to check whether an EBS disk exists. It tells Kubernetes about the storage and how to access it.

Imagine you're using AWS EBS with Kubernetes.

EBS volume = The actual disk in AWS that stores data.

PV (PersistentVolume) = The Kubernetes object that represents that EBS storage.

PVC (PersistentVolumeClaim) = The application's request for storage.

Pod = The application that uses the storage.

PVC
====
it is claiming the PV that it needs storage. Here pvc asking pv I need storage so I am claiming.

kid -> mother -> father -> wallet
Pod ->	PVC	  ->	PV	-> EBS

create order:

delete order:
